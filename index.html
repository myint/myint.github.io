About

I'm a robotics software engineer at JPL and group lead of Robotic Operations and Tools (358T). I've been at the lab since 2007, when I started as a student intern.

On Mars 2020 I led development of SSim (Surface Simulation), which runs the rover's flight software against every command sequence before we uplink it to Perseverance, and I used it to fuzz the flight software. I also wrote parts of the rover's flight software, including the module that commands the Ingenuity helicopter. In operations I've been a Helicopter Integration Engineer and, since 2022, a rover driver.

Since 2023 I've worked on the rover flight software and simulation for Perseverance's onboard global localization. It runs on a commercial Snapdragon processor in the rover's helicopter base station, so we also had to protect it from radiation in software. I'm now PI of a JPL task to make surface operations cheaper: SpaceWasm, portable global localization, learned navigation, and automated downlink and sequencing tools.

Before that I led robotic simulation for InSight, and later was simulation lead for Mars Sample Return and ground software lead for CADRE. Outside JPL I used to develop the Python tools pyflakes and autoflake.

Work

2026–present

PI, Low-Cost High-Performance Surface Operations for Mars, Moon, and Beyond

A JPL strategic R&TD task to make surface operations cheaper: more autonomy on the vehicle, more automation on the ground, for any mission and not just Mars 2020. Each piece is tested against Mars 2020 data on flight or flight-like hardware.

  • SpaceWasm: a flight-compliant WebAssembly interpreter, so one autonomy implementation can run sandboxed on different vehicles and flight software. It's integrated into F Prime. Firefly is integrating it, and Moonfall and Skyfall are evaluating it. GitHub featured it in Octoverse 2026.
  • Global localization without GPS, extended beyond Perseverance to the Moon and to helicopters. All of the lunar terrain vehicle vendors have said they intend to use it.
  • A traversability model pretrained on about 10,000 Perseverance image/waypoint pairs. Its maps feed the ENav planner, and it runs on the Scarecrow test rover.
  • DownlinkDigest, which writes telemetry summaries from downlink. It could save about two hours per planning cycle.
  • SequenceAgent, which generates, simulates, and validates command sequences. We demonstrated it on Perseverance abrasion planning.

2023–present

Perseverance Onboard Global Localization

Perseverance's position uncertainty grows as it drives. When it gets too large the rover stops and waits for the ground to relocalize it. Onboard global localization matches NavCam panoramas against a HiRISE orbital map on board instead. Over 264 panoramas the error averaged 0.36 m. It runs on the Snapdragon 801 in the Helicopter Base Station, the commercial processor that relayed Ingenuity's data, as a co-processor to the rover's RAD750.

  • Worked on the rover flight software: commands to send arbitrarily large files to the base station, wait on it, and bring results back without making a data product, and to apply the localization result to the rover's pose.
  • Extended SSim with part of the base station's F Prime flight software and a simulated serial link to the rover. It ran the whole rover–base station exchange end to end in under a minute, and was the main testbed for the flight software updates.
  • The Snapdragon isn't radiation hardened. On Mars, weak DRAM bits made redundant runs disagree. We fixed it in software: a memory test, a program that keeps bad pages out of use, CPU throttling, and a rover flight software hot patch that accepts two runs that agree within 10 cm.
  • With Columbia University, worked on software radiation protection for commodity processors in space (HotNets '23, ASPLOS '26). Radshield's version of the localization ran in 26% of the time of the serial, radiation-hardened approach.
  • First closed-loop use was on sol 1762 (February 2, 2026), after a 159 m autonomous drive. Position uncertainty went from 8.4 m to 1.5 m.

2015–present

Mars 2020 (Perseverance)

Simulation Lead (2015–) · Flight Software Developer (2016–) · Helicopter Integration Engineer · Rover Planner (2022–) · Mobility Downlink Engineer

  • Led a team of ten building SSim. SSim takes the command sequences, the onboard state from the latest downlink, terrain maps, and onboard files, and runs the rover's flight software on them. It outputs the event records and the rover's kinematic state history. Every plan is simulated in SSim before uplink. Robotic operations runs about 60 simulations per planning day, about 20 seconds each.
  • Led development of RSVP for Mars 2020. MobSketch shows SSim results next to the planned drive, so rover planners can change drives until uplink lockdown instead of freezing them early as on MER and MSL.
  • Fuzzed the flight software through SSim with AFL and with a Python fuzzer against SSim's web service. Both generate command sequences from the flight command dictionary. They found tens of fatal flight software bugs, which were fixed before we hit them on Mars. Static analysis with commercial, open-source, and in-house tools found hundreds more before integrated testing.
  • Wrote the rover flight software module that commands Ingenuity. In operations I was a Helicopter Integration Engineer, the rover-side role that plans each sol's helicopter commanding and the rover's relay of its data.
  • Wrote a flight software module for rover navigation, and led two other developers writing the PIXL instrument manager.
  • Worked around a hardware camera problem in software. Without the workaround the rover assembly schedule would have slipped about a month.
  • Set up continuous integration for flight software in place of the weekly build. Wrote a build system that built the flight software in minutes instead of an hour.
